# FF Shop — commerce blueprint

**Source declared.** The homepage links category routes for all products, chairs, tables and lamps, individual furniture routes, three news details and legal/help pages. It declares a Frameship Shopify integration configuration and embeds escaped variant records. These include variant IDs, titles, selected material options, amount/currency pairs, image metadata and `availableForSale` values. This capture contains usable commerce fields, but it is not a complete, current catalog export. Quantity inventory, successful cart requests, checkout and payment were not verified. The official phone reference depicts product media, description/material rows, price, quantity controls and Add to Cart; a promotional image does not establish working behavior.

**Recommended records.** Keep a product record with `id`, `handle`, `title`, `categoryIds`, `description`, `materialDescription`, ordered `media`, `variantIds`, `newFlag` and related editorial IDs. Each media item needs URL, dimensions, crop/focal point and authored alt text. Keep variants separate: `id`, `productId`, `title`, `selectedOptions[{name,value}]`, `price{amount,currencyCode}`, optional comparison price, image reference and availability snapshot with retrieval time. Money should remain decimal data until display formatting. Add dimensions, delivery lead time and provenance only from verified merchant data.

A cart record should hold `id`, `lines[{id,variantId,quantity}]`, localized monetary totals, currency, timestamps and a provider checkout URL. Treat prices and eligibility returned by the commerce provider as authoritative. Recheck variant availability when adding and before checkout; do not present the source’s boolean as a real-time stock guarantee.

**Editorial and locations.** News is evidenced through image/title/date cards and routes. Recommended CMS records add slug, publication date, excerpt, body blocks, ordered media and product relationships. Stockists are described in source metadata, but the captured home HTML supplies no stockist records. A stockist CMS can hold name, address, country, coordinates, contact, opening information and verified external URL; populate it only from supplied data.

**Purchase and language flow.** Recommended flow: category grid → product detail → material/variant selection → quantity → provider-backed bag → checkout handoff. Implement empty, loading, unavailable and failure states explicitly. The homepage bag/search structures do not prove this flow works. Footer localization declares a select with English only. Optional additional locales require translated product/editorial content, locale-aware formatting and persistent selection. Newsletter submission requires a separately verified endpoint; its required email field alone proves no delivery.
