Source scope: public home HTML/CSS, official marketplace reference artwork and public `/join` HTML/CSS. SOURCE DECLARED means authored source declarations; OPTIONAL RECOMMENDATION is implementation guidance. Membership access, applications, theme persistence, payment and actual community participation were not exercised.

## 1. Layered wordmark, community nav and hero collage

SOURCE DECLARED: the logo component contains repeated Letter K0 / E1 / E2 / P3 elements. The Desktop navigation carries Membership, Inside, Events, Resources and Stories links; Request Access resolves to `/membership`, whereas the Phone action and hero Apply for a seat resolve to `/join`. The hero pairs a bracketed IBM Plex Mono label, Clash Grotesk 76px/76px weight-700 title, Fira Sans supporting copy and paired pill actions with a titled photograph collage. The source declares hero Copy appear motion from y20/opacity .001 to y0/opacity 1 with .55-second spring and .25 bounce.

OPTIONAL RECOMMENDATION: expose one accessible brand name despite repeated decorative letter layers. Keep application and exploration actions distinct and retain their actual source destinations until route changes are intentional. Group the photographs into one decorative collage with sensible alt handling; avoid making every floating frame a dead control. Apply the source 54px tablet and 40px phone display presets and preserve readable final state when animation is disabled.

## 2. Crossing statistic tapes

SOURCE / OFFICIAL REFERENCE: Tape has Band A and Band B, visually crossing near the hero's lower edge. The repeated tiles alternate light, dark and orange treatments and show membership, open seats, years running, renewal rate, countries and rating values. Inline tape text uses Fira Sans 14px/16.8px, weight 700. The markup does not establish that these metrics are real or that their runtime motion was tested.

OPTIONAL RECOMMENDATION: create one data list and render decorative copies from it. Announce each metric once to assistive technology and hide duplicated loop segments. Supply a static strip under reduced motion; offer pause if continuous movement is recreated. Replace sample membership figures with approved values before publishing. Use overflow clipping around the strips without clipping nearby application buttons or keyboard focus.

## 3. Four-step application explanation

SOURCE DECLARED: How It Works carries the title Four steps to the table and numbered modules: Tell us why, Get reviewed, Take your seat, Actually show up. The numbers are IBM Plex Mono 13px/15.6px weight 600, while hand-styled step titles use Clash Grotesk 18px/21.6px weight 600 and -.3px tracking. Body text explains application intent, review, weekly calls and showing up. This is explanatory marketing content rather than proof that a review workflow runs.

OPTIONAL RECOMMENDATION: model the steps as a semantic ordered list. Keep explanation and expected outcome together in each card. At mobile sizes, retain 01→04 order and avoid duplicating the review promise in several places. If adapting the review window, use the actual operational policy provided by the community owner. A submitted application should lead to a clear confirmation with expectations only after a configured submission endpoint confirms receipt.
