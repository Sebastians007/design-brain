# Docspace component recipes

Evidence: Soyeb's official Marketplace listing, four official JPGs, selected primary `/docs` public HTML/CSS and secondary `/docs/introduction` public HTML/CSS. Official image 01 shows an article reading screen; image 02 packages the separate product hub. The selected primary reference is the documentation hub with its real sidebar, not that promotional product hub. Scenic backdrops and price labels belong to Marketplace presentation artwork. All behavior below is either a public declaration or explicitly optional guidance; no live search, clipboard, feedback or backend was tested.

## 1. Two-tier global masthead and search affordance

SOURCE DECLARED: the top tier contains a 24px Geist wordmark, documentation search label, theme toggle, a GitHub count/status component, Pricing and Sign up. The second tier places Documentation, API Reference, Components, Guides and Resources alongside a language selector. Desktop gutters declare 32px; tablet 28px; phone 16px. The search label is Geist 14px, weight 500, line-height 1.2em, while tablet search uses 13px. Primary navigation is a distinct 14px/1.2em role. The active Documentation item has a line layer and a violet accent. Search shortcut text is `/`; do not substitute another shortcut merely because it is common elsewhere. OPTIONAL RECOMMENDATION: implement the search trigger as a labelled button opening a focus-managed dialog, retaining the visible shortcut as supplementary instruction. Define query, pending, results, empty and error views only after an index is configured. Replace preview pricing destinations with owner-provided links. The GitHub source has an unavailable/busy state, so use a static unavailable label until a verified counter is supplied.

## 2. Grouped persistent documentation sidebar

SOURCE DECLARED: Left Sidebar declares fixed positioning, desktop width/max-width 280px and tablet width/max-width 240px. Its Docs Menu has open topic groups and linked pages. Group headings are Geist 15px, weight 500, line-height 1.2em, tracking -0.02em; individual rows use the same size/weight but 1.1em line-height. The row Content Wrap declares padding 10px 14px 10px 24px. A bottom View Changelog action is separate from the topic hierarchy. Source phone visibility hides the desktop sidebar and exposes menu access. OPTIONAL RECOMMENDATION: build the taxonomy as groups containing ordered links with persistent IDs and active-page state derived from route, not link text. Keep the sidebar's scroll separate from the reading rail, and make the active item visible when moving to another article. Compact navigation should preserve the same taxonomy and return focus to its trigger after dismissal. Closing a group must not remove the current article's contextual path or require hover to reopen it.

## 3. Documentation hub category grid

SOURCE DECLARED: central hierarchy is Main > Section > Container > Content Wrap > Main Content, followed by Breadcrumb, a Header with Documentation title/description, and Content. The inner container declares max-width 700px; content gap is 52px desktop, 48px tablet and 42px phone. The category grid has two columns and 16px gap on desktop, then one column under the phone boundary. The title base preset is Geist 32px, weight 500, line-height 1.2em and tracking -0.03em; media variants are 30px and 28px. Each topic card combines a 20px heading (110% line-height, -0.3px tracking) and 14px supporting text. The six cards mirror the sidebar's major groups. OPTIONAL RECOMMENDATION: use shared collection records for grid and sidebar, storing card descriptions separately from article titles. Each entire card can be a normal link with visible focus, while icon or chevron remains decorative. Preserve task order so newcomers see setup before advanced topics. Do not manufacture a marketing hero image above this hub.

## 4. Article reading blocks, code and right on-page rail

SOURCE DECLARED: the inspected introduction article reuses the shell and breadcrumb but expands the central rail with h2/h3 sections, note/tip callouts, code examples, tables, parameter badges, a prompt component and questions. The unconditional desktop presets are h1 32px/38.4px, h2 28px/33.6px, h3 24px/28.8px and body 16px/22.4px. Secondary source emits compact presets before unconditional rules; the authored token rows deliberately correct the helper's first-match 30px/26px/15px values. Native pre uses Fragment Mono 15px weight400, tracking -0.01em and 1.35em line-height. Code header has a bash tab and Copy code button. Right Sidebar is sticky, 25% width/max-width340px and hidden on tablet/phone; ON THIS PAGE is 12px Geist. OPTIONAL RECOMMENDATION: generate TOC entries from structured headings with stable unique IDs; source does not establish their final dynamically generated IDs. Preserve code text exactly when copying and announce clipboard success only after the browser operation succeeds. Tables should use semantic headers; code/table overflow must remain inside its rail. Rendering diagram is a source placeholder, not proof of a completed illustration.

## 5. Article feedback, update metadata and next-page navigation

SOURCE DECLARED: article tail contains Feedback Form, Bottom Navigation with Go to Back/Go to Next, and Last Updated. Custom feedback prompt is Geist16px weight500/1.4em with -0.01em tracking, and controls include Positive, Negative and Feedback labels. Prompt-copy controls and Copy Page are also declared. Native table/code/custom feedback nodes are retained in documentation-custom-declarations.json because the generic h/p collector misses several roles. OPTIONAL RECOMMENDATION: keep the last-updated value as editorial metadata and next/previous order as navigation metadata, independent of publication date. Define feedback idle, selected, detail-entry, sending, acknowledged and retry states once a destination is supplied. Offer a non-submitting local demo when backend is absent; never imply that votes were recorded. Prompt/code/page-copy controls need distinct labels and content targets. The footer's Pages, Categories, Legal and Company columns should remain content links, with placeholder contacts replaced during adaptation. Theme transitions may be reduced to immediate palette changes under reduced motion.
