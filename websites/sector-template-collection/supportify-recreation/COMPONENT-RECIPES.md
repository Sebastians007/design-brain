# Supportify component recipes

Evidence: Anton Radionov's official Marketplace listing, four downloaded official JPGs, primary Help Center public HTML/CSS and one fetched public article route. Official image01 shows the light hub; image02 shows a dark hub with a compact category view. Source color-scheme alternatives are recorded separately. Search, newsletter delivery, support tickets and CMS editing remain untested.

## 1. Service navigation and plain Help Center introduction

SOURCE DECLARED: Desktop, Tablet and Mobile Closed navigation variants identify Supportify alongside Help Center, Style Guide, Changelog, Contact and Contents links, plus a Search Icon control. The wordmark is Inter16px weight700/1.5em. Other navigation uses Inter16px weight500/1.5em. The Help Center h1 declares48px weight700/1.2em on desktop, then40px on tablet and phone. Its supporting description is20px weight400/1.4em. Content declares120px80px desktop padding and80px40px tablet padding, with a1080px maximum inner wrapper. This is a service entry page with generous whitespace, not a promotional feature banner. OPTIONAL RECOMMENDATION: expose the mobile menu as a labelled toggle retaining all support destinations; make Search Icon keyboard-accessible with text in its accessible name. Keep the introductory sentence concrete about what customers can find. Product-specific branding should alter logo and copy without adding a large stock-photo hero that dilutes the support hierarchy.

## 2. Collection rows with icon, excerpt and chevron

SOURCE DECLARED: Categories contains six collections in a two-column grid. Each linked component pairs a small topical icon/title/chevron row with an excerpt and one bottom divider. Collection title shares the16px weight500 interface role; excerpt is16px weight400/1.5em. Source grid gap is20px desktop and40px tablet; phone uses one column. Topic names and slugs are explicit source taxonomy rather than inferred marketing sections. OPTIONAL RECOMMENDATION: model each collection with title, slug, icon, explanatory sentence, order and article membership. Use a single normal link per row, keep chevron decorative and let a long title wrap without colliding with it. A visible focus outline can encompass the whole row. Use icons that match the collection topic and preserve the tiny outlined scale; do not turn every collection into an illustrated card. The divider establishes row grouping and should remain low contrast in both themes.

## 3. Quick-answer index with direct article links

SOURCE DECLARED: Quick Links follows Categories and has its own24px weight700/1.2em heading. Collection rows link to eight concrete `/articles/...` destinations. The compact question labels carry the16px medium navigation role, with chevrons and rules. Source collection repeats two columns wide and one on phone. Quick Links is distinct from the category index: it prioritizes individual answers rather than another copy of collection cards. OPTIONAL RECOMMENDATION: store featured-answer ranking separately from article publication order. Select high-frequency questions with readable titles and ensure each row lands directly in a complete article. A task-based question should name the user's action and result; avoid vague labels requiring customers to open every article. If product taxonomy changes, update this index and breadcrumb memberships together. Preserve normal-link behavior before adding search, analytics or hover animation.

## 4. Customer support article and escalation block

SOURCE DECLARED: the fetched `/articles/how-to-use-my-template-effectively` article starts with a Setup sorcery collection breadcrumb, h1, dek and structured reading body. Article h1 is32px/1.2em on desktop and26px under1199px; h2 is24px/1.2em, h3 is20px/1.2em and body is16px/1.5em. Inline illustrations, lists and related article links appear before an assistance block with a Contact Support action. Multiple copies of body content in the raw source reflect responsive/component serialization; they must not become repeated paragraphs in the final page. OPTIONAL RECOMMENDATION: keep one semantic article body with genuine heading hierarchy, readable image alternatives and a collection-return breadcrumb. Related articles should express topic adjacency, while Contact Support supplies an escalation route for customers whose issue remains unresolved. Do not insert a developer-docs sidebar into this article merely because the sibling Docspace kit uses one. Supportify's examined reading pattern is a simpler editorial support page.

## 5. Bordered newsletter panel, footer and color themes

SOURCE DECLARED: the home tail has Join newsletter, supporting copy, Newsletter Form with email field and Subscribe action, plus consent text. Desktop panel declares80px padding; compact variant40px20px. Subscribe is Inter16px weight500/1.2em; consent14px weight400/1.4em. Footer repeats the primary support destinations and brand. Base canvas token is rgb245,245,247; dark mode changes it to rgb30,30,36 and inverts black/white opacity text tokens. There is no verified manual theme-switch control. OPTIONAL RECOMMENDATION: keep the panel visually separate from the answer index and attach it to one configured mailing provider. Validate email, announce submission status and provide an intelligible retry state; success should require an actual provider acknowledgement. Avoid using this optional subscription form as the only way to ask for support. Reuse a coherent monochrome palette in both schemes rather than adding a bright marketing accent. Respect OS theme preference unless a separately designed manual preference is intentionally added and tested.
