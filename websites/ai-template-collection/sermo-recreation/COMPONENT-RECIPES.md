# Sermo component recipes

Evidence: Masood Ahmad's official Sermo Marketplace listing, four official reference images, public home HTML/CSS, and the declared Documentation route's public source. These recipes describe construction priorities without claiming live voice, model training or integration behavior was tested.

## 1. Spectrum-backed hero and capsule navigation

SOURCE DECLARED: the page opens with a near-black canvas, capsule navigation, release badge, wide headline and two actions. A named radial-spectrum component sits behind the content; Marketplace imagery shows warm orange rays around a dark center. BDO Grotesk Variable declares the hero at 76px/1.02em, CSS weight 400 and independent wght axis 400. OPTIONAL: keep the spectrum behind a contrast-preserving overlay and use a static fallback if WebGL is unavailable. Give decorative signal no pointer handling. Keep brand, routes and utility actions as three visual clusters so the navigation does not read as one overloaded toolbar.

## 2. Command console and live-call indicator

SOURCE DECLARED: an inset console includes a heading, prompt-like field, mode labels and suggestion rows; a live-call card adds channel and duration context. Console heading type is 22px/1.2em with wght 470, despite CSS weight 400. OPTIONAL: create a constrained demonstration that changes local sample content when a suggestion is selected. Separate a decorative prompt from an editable field through clear labeling. Represent live, queued, completed and failed outcomes without fabricated operational status. Pair the waveform with transcript text and an explicit playback control. Reserve stable dimensions so asynchronous content does not move the hero actions.

## 3. Composer steps and continuous-learning scene

SOURCE DECLARED: Composer uses five numbered stages beside an agent setup preview. Improve introduces learning capabilities, while Smart Insights is a separate frame containing ticket-driver bars and Signal detail. OPTIONAL: use one selected step to update the adjacent preview, maintaining the same scene dimensions. Keep selection, completion and progress visually distinct. In the analytical scene, label percentages and their scope instead of relying on bar length alone. Describe suggested policy changes as proposals awaiting review unless the implementation truly supports automatic updates. Preserve these sections as a sequence; collapsing them into a bento grid removes the relationship between setup and improvement.

## 4. Voice Layer product card

SOURCE DECLARED: the natural-voice section leads into a separate scenic card with product detail, capability list, waveform panel, time indicator and transcript example. A paused state is named in the source. OPTIONAL: place the image behind a dark readability overlay and treat the audio panel as a foreground application surface. Use idle, loading, playing, paused, finished and unavailable states with visible button labels. Highlight the active transcript sentence without hiding previous turns. Keep interruption handling as explanatory content until a genuine barge-in system is connected. Reduced motion should freeze the waveform while keeping elapsed time and transcript meaningful.

## 5. Integration wall, customer spotlight and wordmark close

SOURCE DECLARED: a layered logo wall surrounds a warm central mark, followed by a customer quotation, portrait and outcome figures. The final footer combines navigation groups with a very large wordmark; its source declares 350px, 250px and 118px size variants, wght 700 and tight tracking. OPTIONAL: build the integration wall as decorative layers with a separate accessible list of supported connectors. Publish only verified connector status and approved customer evidence. Let the spotlight breathe before the closing CTA. Clip the giant wordmark within its own container so it cannot force horizontal scrolling, and preserve ordinary footer links as readable foreground content.
