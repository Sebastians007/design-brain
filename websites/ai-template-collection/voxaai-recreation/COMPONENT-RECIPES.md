# VoxaAI component recipes

Evidence: Rupak Goura's official VoxaAI Marketplace listing, two official reference images, and the public preview's saved HTML/CSS. The root's desktop browser observation additionally shows the hero waveform. Numbers below distinguish declarations from optional construction choices. Public imagery is reference evidence, not a license to redistribute an editable template.

## 1. Floating navigation and centered introduction

SOURCE DECLARED: the navigation is a charcoal rounded rectangle with a blue symbol tile, compact section links and a white demo action. A closed mobile variant exists. Inter supplies the interface hierarchy: navigation 14px/1.3em at 400; the desktop hero uses 60px/1em at 500 with -1px tracking. Keep the main statement centered above supporting copy and two adjacent actions. OPTIONAL: constrain the introduction to a readable measure and use a 70px desktop gutter. Treat the navigation as a complete unit; its small corner radii should not become exaggerated pill corners. Avoid carrying the Marketplace's tilted white panels into the actual page.

## 2. Role-based conversation preview

SOURCE DECLARED: three agent-role labels appear over a bordered demonstration surface. The initial text resembles an agent response rather than a user form. ROOT BROWSER OBSERVATION: the visible desktop version contains typed transcript content and a central waveform. Audio capability remains untested. OPTIONAL: implement a keyboard-operable tab list with one selected agent, matching transcript panel and explicit sample-audio control. Use fixed sample content to stabilize height between roles. Reserve space for stopped, loading, playing and unavailable states; do not imply that the displayed transcript proves a live CRM action. Keep a text equivalent beside any waveform so the demonstration remains useful without sound.

## 3. Illustrated capability rows

SOURCE DECLARED: the feature area pairs product explanations with language configuration, CRM connections and a low-latency conversation visual. White cards sit against pale blue textured scenes. The desktop h4 preset is 36px/1.2em at 500; compact presets are 32px. OPTIONAL: build each illustration from independent background, white application panel and foreground controls. Preserve the language rows and primary-language badge as recognizable UI. For the CRM scene, keep connector lines behind logos rather than intersecting text. On phone, place the explanation before the illustration and let decorative grain crop independently.

## 4. Billing selector and three-plan comparison

SOURCE DECLARED: pricing sits on the home page with monthly/yearly labels, a savings badge and three plan cards. The middle plan receives blue emphasis and a recommendation band. Plan names use a 28px/1.3em desktop h5 preset. ROOT BROWSER OBSERVATION: clicking Yearly did not establish a price change. OPTIONAL: make billing period a real state shared by every plan; identify currency, period, included minutes and overage together. Use a deterministic data table for monthly and annual values. Maintain the same benefit order across cards, and mark unavailable purchase actions clearly during implementation.

## 5. Proof, questions and closing invitation

SOURCE DECLARED: review cards use prominent quotation marks, portraits and role attribution; practical FAQ rows precede a blue textured CTA and multi-column footer. OPTIONAL: connect each testimonial to approved evidence before publishing. Give FAQ triggers button semantics, expanded state and visible focus. The closing invitation should preserve the paired deployment/sales choices without creating a third competing action. Stack footer groups by their existing Product, Company and Resources sequence on phone. Links labeled About, Careers and Contact currently resolve to home, so separate destination pages would be an explicit extension.
