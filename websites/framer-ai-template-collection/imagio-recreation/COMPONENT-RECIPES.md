# Imagio — component recipes

Basis: official marketplace imagery and public preview HTML/CSS. **SOURCE DECLARED** describes the reference; **OPTIONAL RECREATION** describes authored implementation guidance. No generation service or completed interaction was tested.

## 1. Image fan and foreground composer

**SOURCE DECLARED.** The hero has twelve named image arms, an overlay, a search region and style-chip structures. The official image shows rounded floral output arranged around a centered composer, with the serif proposition beneath. The principal title declares Halant 88/96.8px at weight 400. The visible generation label has a TASA nested span overriding its generic Inter parent.

**OPTIONAL RECREATION.** Give the central tile the most upright crop, then rotate neighboring tiles progressively without rotating their semantic content. Overlay a cream composer with a fine multicolor edge. Use a real labeled textarea, selectable style chips and a clearly named preview action. Support empty, edited, selected-style, preview-loading, preview-ready and failure states using curated example output. Place status below the controls. 

## 2. Three-stage workflow cards

**SOURCE DECLARED.** The first identically named feature section contains three process cards. Fira Code marks the indices; Halant titles and TASA paragraphs provide the explanation. Each card has a small product-control illustration rather than a full dashboard.

**OPTIONAL RECREATION.** Create a shared card shell with a pale visual compartment above a title and one concise explanation. Keep visual compartment height consistent so the three headings align. Build the illustrations as independent prompt, style and output modules. On narrow screens stack the sequence vertically and place indices first in reading order. 

## 3. Capability bento and output comparison

**SOURCE DECLARED.** The second feature section mixes a prompt/output card, style selection, history, resolution comparison, speed illustration and rights illustration. The official reference makes the comparison tile taller and uses multiple smaller pale cards around it.

**OPTIONAL RECREATION.** Build named grid areas rather than relying on arbitrary item spans. Keep each visual treatment subordinate to its heading. A comparison handle should be keyboard adjustable, expose its percentage and offer simple before/after buttons. Do not equate a decorative progress label with measured service speed. Replace broad rights language with approved product terms before treating the tile as evidence.

## 4. Creator solutions and metric pairing

**SOURCE DECLARED.** Four numbered audience modules pair use-case copy with an image and a large demonstration metric. Desktop and smaller-layout variants repeat content in the public source. Fira Code metric styling declares an 80px size with 110% line height.

**OPTIONAL RECREATION.** Use one data model for audience label, practical task, output image and metric explanation.  Replace template metrics with supported facts or omit the metric region. For mobile, present complete audience cards in order rather than hiding all but one behind hover. 

## 5. Quiet FAQ and closing invitation

**SOURCE DECLARED.** FAQ precedes a combined closing invitation/footer family with desktop, tablet and phone variants. The footer includes navigation, legal/social destinations, a newsletter input and attribution.

**OPTIONAL RECREATION.** Use native disclosure controls with a strong focus ring and meaningful question headings. Give newsletter fields explicit labels, validation and a submitted confirmation only after a real integration succeeds. Avoid reproducing surrounding marketplace teal artwork or template-purchase furniture as site content.
